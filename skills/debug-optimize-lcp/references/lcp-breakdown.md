# 最大内容绘制（LCP）分解

LCP 衡量从用户开始加载页面到视口内渲染出最大图像或文本块的时间。为提供良好用户体验，网站应努力让至少 75% 的页面访问 LCP 不超过 2.5 秒。

## LCP 的四个子部分

每个页面的 LCP 都由以下四个子类别组成。它们之间没有间隙或重叠，相加即为完整 LCP 时间。

| LCP 子部分 | 占 LCP 比例（最优） | 描述 |
| ----------------------------- | ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **首字节时间（TTFB）** | ~40% | 从用户开始加载页面到浏览器收到 HTML 文档响应的第一个字节的时间。 |
| **资源加载延迟** | <10% | 从 TTFB 到浏览器开始加载 LCP 资源之间的时间。如果 LCP 元素不需要加载资源（例如系统字体文本），此时间为 0。 |
| **资源加载时长** | ~40% | 加载 LCP 资源本身所需的时间。如果 LCP 元素不需要加载资源，此时间为 0。 |
| **元素渲染延迟** | <10% | 从 LCP 资源加载完成到 LCP 元素完全渲染之间的时间。 |

## 分解为何重要

优化 LCP 需要识别这些子部分中哪一个是瓶颈：

- **TTFB 与 FCP 之间差值大**：表明浏览器需要下载大量阻塞渲染的资源，或需要完成大量工作（例如客户端渲染）。
- **FCP 与 LCP 之间差值大**：表明 LCP 资源无法立即供浏览器优先处理，或浏览器在显示 LCP 内容前还在完成其他工作。
- **资源加载延迟大**：表明资源无法被尽早发现，或被降低了优先级。
- **元素渲染延迟大**：表明渲染被样式表、脚本或长任务阻塞。
