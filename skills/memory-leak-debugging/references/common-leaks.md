# 常见内存泄漏

使用 Chrome DevTools MCP 内存工具分析保留路径、支配链或类差异时，留意代码库中的以下常见模式：

## 1. 未清理的事件监听器

绑定到全局对象（如 `window` 或 `document`）或长生命周期对象上的事件监听器，会阻止其回调中引用的对象被垃圾回收。

**修复：** 组件卸载或监听器不再需要时，务必调用 `removeEventListener`。

## 2. 游离的 DOM 节点

DOM 节点已从文档树中移除，但仍被 JavaScript 变量引用。游离状态是内存泄漏的良好信号，但不一定是 bug。例如，网站有时会故意缓存游离的导航树。

**修复：** 先向用户提示这些游离节点。在置空引用或修改代码前，**先询问用户**，因为游离节点可能是有意缓存的一部分。确认是泄漏后，确保节点移除时将持有 DOM 引用的变量设为 `null`，或限制其作用域。

## 3. 意外的全局变量

未用 `var`、`let` 或 `const` 声明（非严格模式下）或显式挂到 `window` 上的变量会永久驻留内存。

**修复：** 使用严格模式，正确声明变量，避免全局状态。

## 4. 闭包

闭包可能无意间在其外层作用域中保留对大对象的引用。

**修复：** 大对象不再需要时将其置空，或重构闭包以避免捕获不必要的变量。

## 5. 无界缓存或数组

用于缓存的数据结构（如对象、Array 或 Map）无限增长。

**修复：** 为缓存设置上限，使用 LRU 缓存，或对与对象生命周期关联的数据使用 `WeakMap`/`WeakSet`。
